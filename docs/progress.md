## Сессия 3. Эталон NT3 и сверки с research

- `mri/nt3.py`: признаки истории из OHLC (копия `nt_segment` research — тест против оригинала бит в бит после float32),
  векторный инференс и поток бар за баром (`StreamingNT3`). Поток = векторный < 1e-10 (синтетика: тонкий / грубый тик,
  пропуски сетки). Глубина: возмущение бара j меняет признаки окон с началом j + 1 … j + 200; close бара s − 1 не входит
  в знаковые P, R1, R3 (тест).
- `mri/research_bridge.py`: копия prepare `research/sumo_class_bars.py` (smc_bars); тест запускает оригинал подпроцессом
  на синтетическом CSV — массивы бит в бит, meta совпадает кроме `created`.
- **R2 ✅** (`docs/checks/nt3/torch_prod_abc.json`): свежий BTC, 25 436 окон; max |Δlogit| вне ничьих 5.4e-6 / 6.7e-6 /
  7.8e-6 (prod a / b / c; порог 1e-4); ничьих 4 (0.016%), max |Δlogit| на них 6.3e-7; расхождений ориентации 0.
  Первое окно research кончается на баре 264 — **R13 подтверждён эталоном** (и golden: первый показанный бар 264).
- **R3 ✅ по решению Фёдора** (против сохранённых logit — нет, причина TF32; `docs/checks/nt3/e2e_refit_*.json`): тот же набор из 104 599 окон VAL BTC, но max |Δlogit| =
  0.0123 ('refit' ALL a), 0.0112 (ALL b), 0.0120 (C a); p99 ~0.004; > 1e-4 у 94% окон. Разбор (`scripts/nt3_r3_probe.py`,
  `docs/checks/nt3/r3_probe.json`):
  - research-код на CPU по файлам, записанным из тех же баров (с smc_bars), = эталону: max 7.9e-6. Значит, семантика
    признаков истории в эталоне — та же, что в коде research;
  - расхождение с сохранёнными logit — шум с корреляцией соседних окон 0.70 (лаг 1), к лагу 64 падает до фона (~0.03):
    источник внутри окна (свёртки), не в 200 барах истории;
  - эмуляция TF32 в свёртках (входы и веса — 10 бит мантиссы, к ближайшему) даёт тот же размер и структуру: p50 6.4e-4,
    p99 3.2e-3, max 1.1e-2, корреляция лага 1 0.56 (наблюдаемое: 8.8e-4 / 4.2e-3 / 1.2e-2 / 0.70). У cuDNN TF32 включён по
    умолчанию на Ampere; эпоха NT3 на пуле шла вдвое быстрее эпохи F3_g (36 против 71 с) при большей сети — похоже, другой
    GPU. У F3_g R3 прошёл (8.9e-6) — его прогоны, видимо, были на GPU без TF32.
  - Гипотеза TF32 проверена прогоном Colab (`scripts/colab_nt3_val_logits.py`, A100, torch 2.11, данные SMC/data/,
    файл `artifacts/calib/nt3_btc_val_logits.npz`): research-код пересчитал logit тех же 104 599 окон с TF32 выкл. и вкл.
    - **TF32 выкл. против эталона**: max |Δlogit| вне ничьих **9.3e-6 / 8.6e-6 / 1.8e-5** ('refit' ALL a, ALL b, C a);
      > 1e-4 — ни одного окна; на 6 ничьих ≤ 1.1e-6, на 299 окнах с полом ≤ 2.4e-6. По порогу R3 (1e-4) — прошло бы.
    - 17 боковых входов research (каждое 10-е окно, 10 460 окон) против эталона: ≤ 9.1e-7 (float32) — признаки истории из
      сырых OHLC на данных Drive те же, что в эталоне (open, диапазоны, путь, R, V).
    - **TF32 вкл. против сохранённых**: 36.5% logit совпадают **бит в бит** (TF32 выкл. — 0%), медиана |Δ| 5.1e-4;
      остальное — другой порядок свёрток cuDNN при другом размере пачки. Причина R3 установлена: сохранённые logit
      VAL посчитаны с TF32 (cuDNN по умолчанию на A100). На калибровку это почти не влияет (шум logit ~1e-3).
  - Формально R3 по записанному тексту (против logit calib npz) не пройден; по logit без TF32 на тех же данных — пройден.
    **Решение Фёдора 2026-10-15: R3 для NT3 засчитан** по logit без TF32 (запись в `docs/rules.md` после прогона; порог
    1e-4 не менялся; калибровка остаётся на сохранённых logit).
